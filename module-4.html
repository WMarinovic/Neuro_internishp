Building the task Python

This module assumes you have worked through Module 2, which built each piece on its own: drawing several stimuli and keeping them on screen, waiting with an escape route, timing a response with the Keyboard, reading stimuli from a file, and saving one tidy row per trial with the ExperimentHandler. We now put all of it together into a complete, runnable experiment that collects data worth analysing, and then we analyse it in R.

Note

The complete script, srtt.py, and the analysis, srtt_analysis.R, are in 4.14. Type the experiment in yourself once if you can; you will absorb far more than by running a finished file.

4.1Why a serial reaction time task?

The serial reaction time task, or SRTT, is one of the oldest and cleanest ways to measure learning that the learner cannot necessarily report. On each trial a target appears in one of four positions and the participant presses a spatially compatible key. Most of the time the positions follow a fixed repeating sequence. Participants are not told this. Their responses nonetheless grow faster over blocks, and faster than can be explained by general practice alone.

We reveal the sequence-specific part of that learning with a simple trick. One block, the probe, abandons the sequence and presents random positions instead. If the speed-up were merely general practice, the probe would look like its neighbours. Instead, reaction times jump back up, and the size of that jump is our measure of how much the participant had learned about the sequence specifically.

4.2The design in one paragraph

Four positions, four circles, four keys (D F J K) pressed with both hands: left middle and index fingers on D and F, right index and middle fingers on J and K. Seven blocks. Blocks one to five and seven follow a twelve-item sequence repeated eight times; block six is random. Reaction time and accuracy are recorded on every trial. The dependent measures are mean correct reaction time per block (the learning curve) and the sequence cost, the difference between the random probe and the sequence blocks that surround it.

Do the task yourself first. This is a browser version of the script you are about to build, with the same design and the same columns in its data file. Use fewer repeats for a quick run: with 2 repeats per block it takes about two minutes. Timing in a browser is approximate.

4.3Settings at the top

We will read the script in the sections marked by its comments. Open a new file in the Coder, save it as srtt.py, and build it up as we go.

Every number you might reasonably want to change lives at the top, named in capitals. This is a habit worth forming: a reader can grasp and adjust the design without reading the logic, and you avoid magic numbers scattered through the code.

The imports come first. The capstone uses six modules: the visual, core, data and gui parts of PsychoPy, the Keyboard from its hardware layer, and two from the Python standard library (os for building the data path, random for the random block). Put them at the very top of srtt.py:

import os
import random
from psychopy import visual, core, data, gui
from psychopy.hardware import keyboard

SEQUENCE       = [2, 3, 1, 4, 3, 2, 4, 1, 3, 4, 2, 1]  # positions 1-4
N_BLOCKS       = 7            # total number of blocks
RANDOM_BLOCK   = 6            # this block is random; the rest follow SEQUENCE
REPS_PER_BLOCK = 8            # repeats of the 12-item pattern per block
RESP_KEYS      = ['d', 'f', 'j', 'k']    # keys for positions 1, 2, 3, 4
RSI            = 0.25         # response-to-stimulus interval, seconds
MAX_RT         = 2.0          # response deadline, seconds
POSITIONS_X    = [-0.3, -0.1, 0.1, 0.3]  # x of the four locations (height units)

4.4Who is sitting down, and where the data go

A small dialog collects the participant code and session. data.getDateStr() stamps the moment, which keeps filenames unique so you never overwrite a participant. The ExperimentHandler works exactly as in Module 2: you hand it the participant details once, then call addData and nextEntry on every trial, and it writes a tidy CSV when the experiment closes.

info = {'participant': '', 'session': '001'}
dlg = gui.DlgFromDict(info, title='Serial Reaction Time Task')
if not dlg.OK:
    core.quit()

info['date'] = data.getDateStr()
os.makedirs('data', exist_ok=True)
filename = os.path.join('data', f"{info['participant']}_SRTT_{info['date']}")

thisExp = data.ExperimentHandler(
    name='SRTT',
    extraInfo=info,          # participant, session and date become columns
    dataFileName=filename
)
Watch out

Everything in extraInfo is copied onto every row of the data file automatically. That is exactly why participant appears beside each trial in R without your having to add it by hand inside the loop.

4.5The window, the four circles, and the keyboard

We draw four grey circles that stay on screen from start to finish. Nothing flickers and there is no fixation cross to flash up between trials: the display is calm, and the only thing that changes is which circle is filled. To mark a target we set one circle’s fillColor to white, and clear it again afterwards. The Keyboard object timestamps presses against a hardware clock, giving reaction times you can trust.

win = visual.Window(size=[1280, 720], fullscr=False, color='black', units='height')
kb = keyboard.Keyboard()

# four circles, always on screen; the target is the one that fills white
circles = [
    visual.Circle(win, radius=0.05, edges=64, lineColor='grey',
                  fillColor=None, lineWidth=3, pos=(x, 0))
    for x in POSITIONS_X
]

def draw_circles():
    for ci in circles:
        ci.draw()

Three more small helpers are defined here too, once, so the rest of the script can call them anywhere. quit_cleanly closes the data file, the window and the program in that order, so an early exit still saves. show_message puts a line of text on screen and waits for space. wait_with_quit, met in Module 2, waits while still honouring the Escape key.

def quit_cleanly():
    thisExp.close()          # write whatever has been collected
    win.close()
    core.quit()

def show_message(text):
    msg = visual.TextStim(win, text=text, color="white",
                          height=0.045, wrapWidth=0.9)
    msg.draw()
    win.flip()
    keys = kb.getKeys(keyList=["space", "escape"], waitRelease=False)
    while not keys:
        keys = kb.getKeys(keyList=["space", "escape"], waitRelease=False)
    if keys[0].name == "escape":
        quit_cleanly()

def wait_with_quit(duration):
    timer = core.Clock()
    while timer.getTime() < duration:
        if kb.getKeys(keyList=["escape"], waitRelease=False):
            quit_cleanly()
Note

Set fullscr=True for real data collection. A windowed display is only for development, when you want to be able to click away to your editor.

4.6One position list per block

Sequence blocks are simply the twelve-item pattern repeated. Random blocks are built position by position, refusing any immediate repeat so that the random condition matches the sequence in never asking for the same key twice in a row. Without that constraint the random block would be artificially easy on repeats and the comparison would be unfair.

def make_block_positions(is_random):
    n = len(SEQUENCE) * REPS_PER_BLOCK
    if not is_random:
        return SEQUENCE * REPS_PER_BLOCK
    seq = []
    prev = None
    for _ in range(n):
        choice = random.choice([1, 2, 3, 4])
        while choice == prev:        # no immediate repeats
            choice = random.choice([1, 2, 3, 4])
        seq.append(choice)
        prev = choice
    return seq

4.7A single trial, timed properly

This is the heart of the experiment, and it runs inside the trial loop that 4.9 wraps around it. That loop hands each trial three things the code below uses: pos, the target position 1 to 4 for this trial; correct_key, the key that matches it, taken as RESP_KEYS[pos - 1]; and trial_overall, a running count across the session. With the four circles already on screen, we fill the target circle white. The instant that fill is on screen we reset the keyboard clock, so the reaction time is measured from the moment the target could first be seen, not from some earlier point. We then poll for a key until either one arrives or the deadline passes, and clear the fill again. Because the circles are never undrawn, the display stays rock steady.

circles[pos - 1].fillColor = 'white'
draw_circles()
kb.clearEvents()
win.flip()
kb.clock.reset()          # time from the moment the target fills

response_key = None
rt = None
while kb.clock.getTime() < MAX_RT:
    keys = kb.getKeys(keyList=RESP_KEYS + ['escape'], waitRelease=False)
    if keys:
        press = keys[0]
        if press.name == 'escape':
            quit_cleanly()
        response_key = press.name
        rt = press.rt
        break

correct = int(response_key == correct_key)
circles[pos - 1].fillColor = None      # clear the target again
Watch out

The order matters: clearEvents() before the flip discards any stray presses from the gap between trials, and kb.clock.reset() comes immediately after the flip so timing starts when the target fills. Reset before the flip and every reaction time is inflated by up to a frame, as the clock demo in Module 2 shows.

Between trials the circles stay on screen as plain outlines during the response-to-stimulus interval, so there is no blank screen and no flicker:

# response-to-stimulus interval: the circles stay visible as outlines
draw_circles()
win.flip()
core.wait(RSI)

A miss leaves response_key and rt as None. Those empty cells become NA in R, which is precisely what R wants for a missing value, so we do nothing special to handle them here.

4.8Recording the trial

Each addData call adds one named value to the current row; nextEntry closes the row and starts the next. Name the columns the way you want to type them in R: short, lower-case, no spaces.

thisExp.addData('block', block)
thisExp.addData('block_type', 'random' if is_random else 'sequence')
thisExp.addData('trial_in_block', trial_in_block)
thisExp.addData('trial_overall', trial_overall)
thisExp.addData('position', pos)
thisExp.addData('correct_key', correct_key)
thisExp.addData('response_key', response_key)
thisExp.addData('correct', correct)
thisExp.addData('rt', rt)
thisExp.addData('rsi', RSI)
thisExp.nextEntry()

4.9Blocks, breaks, and a clean exit

The block loop wraps the trial loop, offering a rest between blocks and stopping cleanly at the end. quit_cleanly() always closes the ExperimentHandler first, so that even an early exit on the Escape key still writes whatever data has been collected. Never let a script simply run off the end with the data unsaved.

trial_overall = 0   # running count across the whole session

for block in range(1, N_BLOCKS + 1):
    is_random = (block == RANDOM_BLOCK)
    positions = make_block_positions(is_random)

    draw_circles()            # settle the display before the block
    win.flip()
    core.wait(0.5)

    for trial_in_block, pos in enumerate(positions, start=1):
        trial_overall += 1
        correct_key = RESP_KEYS[pos - 1]   # the key matching this position
        # --- run the single trial from 4.7 here ---
        # (fills the target, times the response, sets response_key/rt/correct)
        # --- then record it, as in 4.8 ---
        # thisExp.addData(...) for each column, then thisExp.nextEntry()

    if block < N_BLOCKS:
        show_message(f"End of block {block} of {N_BLOCKS}. "
                     "Take a short break. Press SPACE to continue.")

show_message("That is the end of the task. Thank you!")
quit_cleanly()
Try this

Run it with REPS_PER_BLOCK = 2 and play the part of a fast learner: deliberately speed up on the sequence blocks. Open the CSV afterwards and confirm a row exists for every trial, with sensible reaction times and a block_type column that switches to random on block six.

4.10The data file

When the experiment closes, the ExperimentHandler writes a wide-format CSV to the data folder with one row per trial. The columns you will use are below; the identifier columns come from extraInfo, the rest from the addData calls.

ColumnMeaning
participantParticipant code typed into the dialog
sessionSession label, useful for test-retest designs
dateTimestamp the session began
blockBlock number, 1 to 7
block_type“sequence” or “random” (block 6)
trial_in_blockPosition of the trial within its block
trial_overallRunning trial count across the whole session
positionTarget location, 1 (far left) to 4 (far right)
correct_keyThe key that was correct on this trial
response_keyThe key actually pressed (empty if no response)
correct1 if the right key was pressed, otherwise 0
rtReaction time in seconds (empty if no response)
rsiThe response-to-stimulus interval used
For R users

Because the file is wide, tidy and one-row-per-trial, readr::read_csv() reads it with no fuss, and the empty rt cells from missed trials arrive as NA rather than zeros, so they will not quietly drag your means down.

4.13The sequence cost

        
Finally we put a number on the bump: the random probe minus the mean of its two neighbouring sequence blocks, computed per participant. A positive value means the sequence was helping.
