Building the task Python

Where the serial reaction time task measured learning through speed, this capstone measures memory through accuracy, and it introduces the analysis framework that underpins a huge amount of memory and perception research: signal detection theory. The build reuses everything you now know (a participant dialog, an ExperimentHandler, the Keyboard, an item loop from a file) and adds a two-phase structure: study, then test.

Note

The complete experiment, recog_memory.py, the analysis, recog_analysis.R, and a starter word pool, memory_words.csv, are in 5.11. Edit the word file freely; the code adapts to whatever pool you give it.

5.1Why a recognition memory task?

In a recognition test we show studied words (targets, or “old”) mixed with unstudied words (lures, or “new”), and the participant judges each one. That simple yes/no decision hides two very different things: how well the person can tell old from new, and how willing they are to say “old” in the first place. A cautious participant and a forgetful one can produce the same number of correct answers for opposite reasons. Signal detection theory pulls these apart.

Every test trial falls into one of four boxes. Saying “old” to an old word is a hit; saying “old” to a new word is a false alarm; the other two are misses and correct rejections. From the hit rate and the false-alarm rate we compute two numbers: d-prime, how far apart the memory signals for old and new items are, which is sensitivity; and the criterion, how much evidence the person demands before saying “old”, which is bias.

Note

The logic is worth holding onto: raise your hits by saying “old” more often and your false alarms rise too, so a generous strategy inflates both. d-prime rewards only the separation between the two rates, which is why it tracks memory rather than willingness to guess.

5.2Settings

Open a new file, save it as recog_memory.py, and build it in sections. The dialog, the ExperimentHandler and the Keyboard are just as in Capstone A, so we concentrate on what is new: splitting a word pool into old and new, and running two phases.

As always, the things you might change sit at the top. The two response keys are named here, so the rest of the code never hard-codes a letter.

STIM_FILE  = 'memory_words.csv'
N_STUDY    = 20          # number of studied (old) words
N_LURES    = 20          # number of unstudied (new) words at test
STUDY_DUR  = 1.5         # seconds each word is shown during study
STUDY_ISI  = 0.6         # blank gap between study words
ITI        = 0.5         # blank gap between test trials
KEY_OLD    = 'o'         # "I saw this word"
KEY_NEW    = 'n'         # "this word is new"

5.3Splitting the pool into old and new

We read the word pool, shuffle it, and slice it: the first N_STUDY words become targets that will be studied, the next N_LURES become lures that appear only at test. Shuffling first means a different random split for every participant, so no particular word is always old. The test list tags each word with its true status and is itself shuffled, so old and new are interleaved unpredictably.

pool = [row['word'] for row in data.importConditions(STIM_FILE)]
random.shuffle(pool)
targets = pool[:N_STUDY]                       # studied (old)
lures = pool[N_STUDY:N_STUDY + N_LURES]        # test-only (new)

study_list = targets[:]
random.shuffle(study_list)

test_list = ([{'word': w, 'status': 'old'} for w in targets] +
             [{'word': w, 'status': 'new'} for w in lures])
random.shuffle(test_list)
Watch out

Slice the lures from a part of the pool the targets did not come from. If targets and lures overlapped, a “new” word might actually have been studied, and the false-alarm rate would be meaningless. Taking pool[:N_STUDY] and pool[N_STUDY:N_STUDY + N_LURES] guarantees they are disjoint.

5.4The study phase

Studying is just viewing: each word appears for STUDY_DUR seconds, then a blank gap. There is no response to collect, but we still want Escape to work, so the waits go through the wait_with_quit helper from Module 2, which polls the keyboard while it waits.

for word in study_list:
    word_stim.text = word
    word_stim.draw()
    win.flip()
    wait_with_quit(STUDY_DUR)
    win.flip()                 # blank
    wait_with_quit(STUDY_ISI)

5.5The test phase, one trial

Each test word appears with a reminder of the keys. We reset the keyboard clock at the flip so the decision time is measured from word onset, then wait for O or N. The trial is correct when the response matches the word’s true status. In the complete script this trial sits inside a loop over test_list, with a blank gap of ITI seconds after each one.

word_stim.text = entry['word']
word_stim.draw()
prompt.draw()
kb.clearEvents()
win.flip()
kb.clock.reset()               # time the decision from word onset

response = None
rt = None
while response is None:
    keys = kb.getKeys(keyList=[KEY_OLD, KEY_NEW, 'escape'], waitRelease=False)
    if keys:
        press = keys[0]
        if press.name == 'escape':
            quit_cleanly()
        response = 'old' if press.name == KEY_OLD else 'new'
        rt = press.rt

correct = int(response == entry['status'])
Note

Notice there is no feedback at test. In a recognition experiment you do not tell the participant whether they were right, because that would teach them the items and contaminate later trials.

5.6Recording the trial

The crucial pair of columns is status and response: the truth and the judgement. Everything in the analysis is built from comparing those two.

thisExp.addData('trial', trial)
thisExp.addData('word', entry['word'])
thisExp.addData('status', entry['status'])      # old (target) or new (lure)
thisExp.addData('response', response)           # old or new
thisExp.addData('correct', correct)
thisExp.addData('rt', rt)
thisExp.nextEntry()
Try this

Run it with a small pool first: set N_STUDY and N_LURES to 4 and trim the word file. Then deliberately answer “old” to everything, and check in the data that your hits are perfect but your false alarms are too, the signature of pure bias rather than memory. You can try the same in the browser version in 5.1.

5.7The data file

The ExperimentHandler writes one row per test trial to the data folder. The study phase is not saved, because the studied words are exactly the rows whose status is old.

5.9Rates, d-prime and criterion

        
Hit and false-alarm rates are just proportions, but a rate of 0 or 1 makes d-prime infinite. The standard loglinear correction adds half a trial to each count and one trial to each total, which nudges extreme rates away from the edges. qnorm turns a rate into a z-score, and the two signal-detection measures follow directly.

5.10Seeing it

        
Plotting each participant as a point of hit rate against false-alarm rate makes the theory visible: anyone above the diagonal is discriminating old from new better than chance, and the further above, the larger the d-prime.

For a real dataset, go trial-level with a probit mixed model, glmer(said_old ~ status + (1 + status | participant), family = binomial(link = "probit")), where the status effect is d-prime and the intercept reflects bias. It uses every response and respects the nesting, rather than reducing each person to two numbers.
