A screener: the ASRS Python

So far every response has been a fast key press. Questionnaires are different: the participant reads a statement and rates it on a scale, and the data are ordinal rather than reaction times. This module teaches that pattern twice. First with a real, widely used screener, the six-question Adult ADHD Self-Report Scale (ASRS-v1.1), which reduces to a single count; then with a 50-item personality questionnaire that has five subscales and reverse-keyed items. You can work through this module before the capstones or after them.

Note

The ASRS-v1.1 Screener is © New York University and Ronald C. Kessler, PhD, all rights reserved, with requests to reproduce or translate directed to Professor Kessler at Harvard Medical School. For that reason its item wording does not appear on this site. Your supervisor will give you the items file, asrs_items.csv; keep the attribution on anything you distribute. Everything here works with the items file whatever its wording, and the example data use item numbers only.

Watch out

The ASRS is a screening tool, not a diagnosis. A positive screen means a fuller assessment may be warranted; it does not confirm ADHD. Say this plainly on screen and in any participant information, because people will inevitably run it on themselves.

6.1Why a questionnaire, and why the ASRS

A questionnaire exercises a different set of skills from the reaction-time tasks. Instead of timing a key press to the millisecond, you present text, capture an ordinal rating, loop over items you have stored in a data file rather than written into the code, and save categorical responses. Almost every applied study mixes a task with at least one questionnaire, so this is a pattern worth owning.

The screener earns its place because its scoring is more interesting than a plain sum. It uses a shaded-box rule: a response counts only if it reaches a threshold that differs across items, and four or more counted items flag a positive screen. Encoding that rule is a genuine recoding exercise in R, much closer to what real instruments demand than averaging a tidy Likert scale.

The five response options map to numbers in the obvious way: Never is 0, Rarely 1, Sometimes 2, Often 3, Very Often 4. The standard form counts an item for the screen when items 1 to 3 reach Sometimes and items 4 to 6 reach Often. We store those per-item thresholds as data so a reader can see and change them.

For R users

Design with the analysis in mind: we save one row per item with its item_no, and we keep the scoring thresholds in the same items file the experiment reads. R then joins responses to thresholds and the screen falls out in a few lines.

6.2The response scale, in one place

Open a new file, save it as asrs_questionnaire.py, and build it up in the usual sections. The participant dialog and the ExperimentHandler are exactly as in the capstones, so we focus on what is new: the rating widget and the item loop.

Name the response labels once. Their order defines the mapping to 0 to 4, so this single line is also the scoring key for the raw responses.

ITEMS_FILE  = 'asrs_items.csv'
RESP_LABELS = ['Never', 'Rarely', 'Sometimes', 'Often', 'Very Often']  # 0..4

6.3A rating widget: the Slider

PsychoPy’s Slider gives you a ready-made rating scale. With style='radio' and integer ticks, it shows one selectable button per option, answered with the mouse. We make the mouse visible because, unlike the reaction-time tasks, here the participant needs it.

win.mouseVisible = True

slider = visual.Slider(win, ticks=[0, 1, 2, 3, 4], labels=RESP_LABELS,
                       granularity=1, style='radio', size=(0.9, 0.06),
                       pos=(0, -0.18), color='white', labelHeight=0.03)
Note

granularity=1 forces whole-number answers, so a respondent cannot land between Often and Very Often. Without it the slider would return continuous values, which is wrong for a categorical scale.

6.4The items live in a file, not the code

data.importConditions reads the items file and hands back a list of dictionaries, one per item, with keys matching the column headings (item_no, shaded_from, item_text). Keeping the items in a file means you can edit, translate or reorder them without touching the program.

items = data.importConditions(ITEMS_FILE)   # a list of dicts, one per item

6.5One item at a time

For each item we show the statement and the slider, and we wait. The loop only lets the participant move on once they have actually chosen an option, so no item can be skipped by accident. Pressing Space with no answer simply does nothing.

for item in items:
    item_text.text = f"{item['item_no']}. {item['item_text']}"
    slider.reset()
    kb.clearEvents()

    responded = False
    while not responded:
        item_text.draw()
        slider.draw()
        prompt.draw()
        win.flip()
        keys = kb.getKeys(keyList=['space', 'escape'], waitRelease=False)
        if keys:
            if 'escape' in [k.name for k in keys]:
                quit_cleanly()
            if slider.getRating() is not None:   # only advance once answered
                responded = True

    # a radio Slider is categorical: getRating() returns the LABEL text
    rating_label = slider.getRating()
    response = RESP_LABELS.index(rating_label)   # map back to its 0-4 code
Watch out

slider.reset() at the top of each item is essential. Forget it and the slider keeps the previous item’s answer on screen, quietly biasing every response after the first.

Note

One quirk worth knowing: a radio Slider is categorical, so getRating() returns the chosen label text, not a number. With word labels like “Sometimes”, int(slider.getRating()) would raise an error, so we look the label up in RESP_LABELS to recover its 0–4 code. A scale whose labels happen to be numerals hides this trap; word labels expose it.

6.6Recording each item

We store the numeric response, its label for readability, and how long the item took from slider.getRT(). One nextEntry per item gives us long-format data, one row per item, which is the friendliest possible shape for R.

thisExp.addData('item_no', item['item_no'])
thisExp.addData('response', response)
thisExp.addData('response_label', rating_label)
thisExp.addData('rt', slider.getRT())
thisExp.nextEntry()
Try this

Run it once and confirm the data file has one row per item, a response from 0 to 4, and the matching label. To adapt it to a different rating instrument later, you only change the wording and thresholds in asrs_items.csv; the code does not change.

6.7The items file and the data it writes

There are two files to understand: the items file you prepare, and the data file the experiment writes. The items file, asrs_items.csv, has one row per item:

ColumnMeaning
item_no1 to 6, matching the numbering on the official screener
shaded_fromLowest response that counts: 2 (Sometimes) for items 1–3, 3 (Often) for items 4–6
item_textThe statement shown to the participant (the official screener wording, supplied separately)

The data file, written to the data folder, has one row per item per respondent:

ColumnMeaning
participantRespondent code from the dialog
sessionSession label
dateTimestamp the session began
item_noWhich item, 1 to 6
responseThe rating, 0 (Never) to 4 (Very Often)
response_labelThe same rating as a word, for readability
rtSeconds taken to answer that item
For R users

Because the scoring thresholds live in asrs_items.csv rather than the data file, R reads both and joins them on item_no. That keeps the thresholds in exactly one place, so a correction is a single edit.

A multi-subscale questionnaire: the IPIP Big Five Python

        
The ADHD screener reduced to a single count. Most questionnaires are richer than that: they carry several subscales, often with reverse-keyed items, and yield a profile rather than one number. This part teaches that step up using the 50-item IPIP version of Goldberg’s (1992) Big-Five Factor Markers: five ten-item subscales, rated on a 5-point scale, with 20 of the 50 items reverse-keyed.

        

          Note
          
The International Personality Item Pool (IPIP) is in the public domain, so its items can be used, shared, reordered and adapted freely. The items, their order and their keys in ipip50_items.csv come from the IPIP website (ipip.ori.org), with two words changed to Australian spelling. Cite the scales as Goldberg, L. R. (1992). The development of markers for the Big-Five factor structure. Psychological Assessment, 4, 26–42.

        

        

          Watch out
          
These scales describe broad personality traits, not abilities or disorders, and fifty items give only a rough picture. Treat your own scores as a demonstration of the coding, not as feedback about yourself, and say the same to anyone you test.

        


        
6.10Why a multi-subscale questionnaire?

        
A single-score instrument like the screener answers one question. A multi-subscale instrument answers several at once, and the coding has to keep them apart. The IPIP-50 is a good teacher because its items belong to five subscales, so scoring means summing within each subscale rather than over the whole, and because many items are worded in the opposite direction, so scoring also means flipping those items first. The subscales are:

        

          
SubscaleTraitItems keyed + / −

          
            
extraversionSociable, talkative, energised by company5 / 5

            
agreeablenessWarm, considerate, interested in others6 / 4

            
conscientiousnessOrganised, careful, reliable6 / 4

            
emotional_stabilityCalm and even-tempered (the opposite pole of neuroticism)2 / 8

            
intellectImaginative, curious, quick with ideas7 / 3

          
        

        
Each item is rated from 1 (Very Inaccurate) to 5 (Very Accurate) as a description of the respondent. Once the reverse-keyed items are flipped, a subscale scores between 10 and 50, with higher meaning more of the trait. The items file lists them in the IPIP’s suggested order, which cycles through the five subscales and alternates the keying, so that respondents keep reading each statement rather than settling into one answer. The teaching goal is the machinery: how to carry per-item metadata in a file, present a longer scale, and turn raw responses into a per-subscale profile in R.

        

          For R users
          
Design with the analysis in mind: every item carries a subscale and a reverse flag in the items file. R reads those, flips the reverse-keyed items, and sums within subscale. Because the metadata lives in one file, correcting a subscale assignment or a reverse key is a single edit.

        


        
6.11Settings, and a five-point slider with anchors

        
Save a new file as ipip_questionnaire.py. It reuses the Slider and the item loop from the screener, with three changes: numbered buttons with word anchors at the ends, a small progress indicator (50 items is a long way), and an items file that carries subscale and reverse metadata which stays out of the data.


ITEMS_FILE = 'ipip50_items.csv'
SCALE_MIN, SCALE_MAX = 1, 5      # 5-point accuracy scale

        
Five radio buttons carry the numbers; two small text labels anchor the ends, which is clearer than trying to squeeze long words under every tick.


slider = visual.Slider(win, ticks=list(range(SCALE_MIN, SCALE_MAX + 1)),
                       labels=[str(n) for n in range(SCALE_MIN, SCALE_MAX + 1)],
                       granularity=1, style='radio', size=(1.0, 0.06),
                       pos=(0, -0.12), color='white', labelHeight=0.03)

anchor_lo = visual.TextStim(win, text='Very Inaccurate', color='grey',
                            height=0.028, pos=(-0.5, -0.21))
anchor_hi = visual.TextStim(win, text='Very Accurate', color='grey',
                            height=0.028, pos=(0.5, -0.21))

        

          Note
          
IPIP items are written as short verb phrases without “I” (“Am always prepared.”), so the instructions do the framing. The complete script opens with the IPIP’s standard instructions, asking respondents to describe themselves as they generally are now.

        


        
6.12The item loop, with a progress counter

        
The structure is the loop you already know. The only addition is a progress line so the respondent can see how far through they are, which matters on a long questionnaire.


for i, item in enumerate(items, start=1):
    progress.text = f"Item {i} of {len(items)}"
    item_text.text = item['item_text']
    slider.reset()
    kb.clearEvents()

    responded = False
    while not responded:
        progress.draw(); item_text.draw(); slider.draw()
        anchor_lo.draw(); anchor_hi.draw(); prompt.draw()
        win.flip()
        keys = kb.getKeys(keyList=['space', 'escape'], waitRelease=False)
        if keys:
            if 'escape' in [k.name for k in keys]:
                quit_cleanly()
            if slider.getRating() is not None:
                responded = True

    response = int(slider.getRating())

        
Here the labels are the numerals 1 to 5, so getRating() returns "3", say, and int() turns it into the number 3. This is the case the Note in 6.5 warned about: the trap is hidden, not gone.

We save the item number and the raw response only. The subscale and reverse flag stay in the items file, where R will pick them up, so that scoring has a single source of truth.

Scoring the subscales in R R

        
Scoring a multi-subscale instrument is three moves: attach each response to its subscale and reverse flag, flip the reverse-keyed items, then sum within subscale. On a five-point scale the flip is six minus the response, so a 1 becomes a 5 and a 5 becomes a 1. In the browser, the data folder holds thirty simulated respondents, with ipip50_items.csv beside it.

          Watch out
          
The subscale map and reverse flags here are taken from the IPIP scoring key. If you adapt the instrument or suspect a mismatch, re-check them against the source: a misassigned item or a missed reverse key quietly distorts a whole subscale, and unlike a typo it produces no error to warn you.

        

        
One way to catch a wrong key is to correlate each item’s raw response with the rest of its subscale, after the other items have been flipped. A −keyed item should correlate negatively before its own flip, and a +keyed item positively. An item with the wrong sign for its key is worth a second look.
