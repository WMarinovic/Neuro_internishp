Troubleshooting

The errors that catch almost everyone, grouped into plain Python mistakes and PsychoPy-specific ones, each with the symptom and the fix. It is worth reading early, not only when something breaks.

Almost every error you meet in your first months is one of a small set. Learning to read the error message and recognise the pattern will save you more time than anything else on this site. The questions below are phrased as you are likely to experience them.

Python: the usual suspects

I get an IndentationError, or the wrong lines seem to run.

Python uses indentation to decide what belongs inside a for, if, def or while. Everything in a block must be indented by the same amount; use four spaces and never mix spaces with tabs. If a line that should sit inside a loop is flush to the left margin, it runs once at the end instead of on every pass, which looks baffling until you see the indentation. Set the Coder to show whitespace and to insert spaces, not tabs.

NameError: name '...' is not defined.

Almost always a typo or the wrong case. Python is case-sensitive, so win and Win are different names, and getKeys is not getkeys. Check the spelling and capitalisation against the line where you first created the name. The same error appears if you use a variable on a line above the one that creates it.

A variable changed by itself, or I get TypeError: 'list' object is not callable.

You reused a name. If you name a variable list, sum, str, or after a module you imported, you overwrite the original and it stops behaving as a function. Give your variables their own distinct names and steer clear of the names of built-ins and modules.

SyntaxError pointing at a line that looks perfectly fine.

Look at the line above it. A missing colon at the end of a for, if or def, or an unclosed bracket or quote, makes Python stumble on the next line. Count your opening and closing parentheses, and check that every for, if and def ends in a colon.

My condition never fires, or I assigned when I meant to compare.

A single = assigns a value; a double == compares. if response = 3 is an error, while if response == 3 is the test you wanted.

Numbers from the dialog or the CSV behave like text.

Values typed into the participant dialog and read from a CSV arrive as strings. '2' + 1 fails, and '10' < '9' is True because it compares text character by character. Convert with int() or float() before doing arithmetic or numeric comparisons. This is exactly why Module 6 writes int(slider.getRating()).

My list index is off by one (IndexError: list index out of range).

Lists count from zero, so a four-item list has indices 0 to 3. That is why position 1 maps to POSITIONS_X[pos - 1]. Reaching past the last index raises that error; an index of 4 in a four-item list is one too far.

I called a function but nothing happened.

You left off the parentheses. core.quit merely refers to the function and does nothing; core.quit() actually calls it. The same applies to win.flip versus win.flip().

PsychoPy: the usual suspects

I draw something but the screen stays blank.

You forgot win.flip(). Drawing paints to a hidden buffer; the flip reveals it on screen. Every visible change needs a flip, and only what you have drawn since the last flip will appear. The draw-and-flip demo in Module 1 shows this.

My stimulus flickers or vanishes between frames.

You are only drawing it on some flips. Anything that should stay on screen must be drawn again before every flip. This is why the reaction-time task redraws all four circles on each trial rather than assuming they linger.

I’m trapped in a full-screen window and cannot get out.

Always build in an escape route that closes the window and calls core.quit(). Develop with fullscr=False so you can click away to your editor, and switch to fullscr=True only for real testing. If you are stuck, Alt+Tab (Windows) or Cmd+Tab (macOS) will get you out.

My reaction times look too long, or suspiciously constant.

Two usual causes. First, timing with time.sleep() or by counting loops instead of using core.wait() and the screen refresh. Second, resetting the response clock at the wrong moment: reset the keyboard clock immediately after the win.flip() that shows the stimulus, never before it, or every time is inflated. The clock demo in Module 2 shows by how much.

Sizes and positions come out wrong.

Check the window’s units. In height units everything is a fraction of the window height and the screen runs from −0.5 to +0.5, so a size of 0.05 is sensible. The same number in pix would be a few pixels. Choose one unit and stay with it.

KeyError: 'item_text' when reading my conditions file.

The column heading in your CSV does not match the key you ask for in code. Headings are case- and space-sensitive, so item_text is not Item Text. Open the file and check the header row matches exactly.

The rating slider keeps the previous answer.

Call slider.reset() at the top of each item. Without it the widget carries the last rating forward and silently biases every response after the first.

ValueError: invalid literal for int() with a Slider rating.

A radio Slider returns the label text, not a number. With word labels such as “Sometimes”, int() fails; look the label up in your list of labels instead, as Module 6 does with RESP_LABELS.index(rating_label).

My data file is empty, or there is no file at all.

Make sure you call thisExp.nextEntry() after each trial and close cleanly with thisExp.close(). A script that crashes or is force-quit before saving loses the run, which is why we route every exit through quit_cleanly() so the handler always saves first. Also confirm the output folder exists with os.makedirs('data', exist_ok=True).

Opening the CSV in Excel scrambled my data.

Excel can change the separator, reinterpret numbers, turn values into dates and alter the text encoding, and it is worse under some regional settings. Read the raw file directly in R rather than re-saving it from a spreadsheet; if you must look in Excel, use its import dialog instead of double-clicking the file.

This website

The Run button in an R or Python box does nothing.

The boxes run only on the live website. A page opened from your own computer (its address starts with file:///) cannot load R or Python, and the box says so. On the live site, the first run on a page downloads R or Python into your browser, which can take up to a minute for R; watch the status line next to the button.

R says “could not find function”, or “object not found”, in a browser box.

Run the boxes on a page in order: later boxes use objects that earlier ones create, and pressing Run on a later box should run the earlier ones first. If you have edited an earlier box, run it again yourself so the later boxes see your change.

Nothing here matches. Read the very last line of the traceback: it names the error type and the line number, and searching for the error type alone (for example TypeError) often finds the entry.

Note

When an error appears, read the very last line of the traceback first: it names the error type and the line number. Nine times out of ten it points you straight at one of the patterns above.
