The pieces of a real experiment Python

Module 1 opened a window, drew one message and waited for a key. That is the whole of a PsychoPy program in miniature, but a real experiment repeats that cycle hundreds of times, draws more than one thing at once, reads the keyboard with proper timing, and saves a tidy row for every repetition. This module builds each of those pieces on its own, in the smallest program that shows it working, so that when the two capstones assemble them you are recognising old friends rather than meeting five new ideas at once. Nothing here is throwaway: every block reappears almost unchanged in the serial reaction time task.

Work through the sections in order and type each snippet into a scratch file you can throw away afterwards, say bridge.py. By the end you will have written, in isolation, every mechanism the capstone leans on.

2.1Drawing more than one thing, and keeping it on screen

Module 1 drew a single stimulus. The rule that governs every display in PsychoPy is simple and worth saying once more: only what you have drawn since the last flip appears at the next one. So if you want several things on screen together, you draw them all, then flip once. And if you want something to stay on screen across many flips, you draw it again before every flip. It never lingers on its own. (The draw-and-flip demo in Module 1 shows this happening.)

from psychopy import visual, core, event

win = visual.Window(size=[1280, 720], fullscr=False,
                    color='black', units='height')

# three stimuli, created once
title = visual.TextStim(win, text='Two circles and a label',
                        pos=(0, 0.35), color='white', height=0.05)
left  = visual.Circle(win, radius=0.08, pos=(-0.2, 0),
                      lineColor='grey', fillColor='grey')
right = visual.Circle(win, radius=0.08, pos=(0.2, 0),
                      lineColor='grey', fillColor=None)

# draw all three, then reveal them together in one flip
title.draw()
left.draw()
right.draw()
win.flip()

event.waitKeys(keyList=['space'])
win.close()
core.quit()
Try this

Comment out right.draw() and run again. What happens to the right circle?

Show what to expect

The right circle vanishes, even though you created it, because you never drew it before the flip. Creating a stimulus and drawing it are two separate acts: creation happens once, drawing happens on every frame it should be visible.

The serial reaction time task uses exactly this pattern. Four circles are created once, and a small helper redraws all four before every flip so the display never flickers. That helper is nothing more than the three draw calls above, wrapped in a function so you do not repeat yourself:

circles = [left, right]

def draw_circles():
    for c in circles:
        c.draw()

draw_circles()   # draws every circle in the list
win.flip()
Note

A list of stimuli plus a loop that draws each one is the standard way to manage a fixed set of objects. When you later see for c in circles: c.draw() in the capstone, it is this and nothing more.

2.2Waiting properly, and always leaving a way out

Two waits appear constantly in experiments: a fixed pause with nothing to respond to (a blank gap between trials, or a word shown for a set time), and a pause that ends when the participant presses a key. The first is core.wait(seconds). Never use Python’s own time.sleep() for this; core.wait() is written to co-operate with the screen refresh, and sleep is not.

The trouble with a bare core.wait() is that the keyboard is dead during it, so a participant cannot quit. In a full-screen study that is a real problem. The fix is a tiny helper that waits in small steps and checks for the Escape key on each one. Both capstones use exactly this, under the name wait_with_quit:

from psychopy import visual, core, event

win = visual.Window(size=[1280, 720], fullscr=False,
                    color='black', units='height')

def quit_cleanly():
    win.close()
    core.quit()

def wait_with_quit(duration):
    timer = core.Clock()
    while timer.getTime() < duration:
        if 'escape' in event.getKeys(keyList=['escape']):
            quit_cleanly()

msg = visual.TextStim(win, text='Waiting 3 s. Press ESC to quit.',
                      color='white', height=0.05)
msg.draw()
win.flip()
wait_with_quit(3.0)
quit_cleanly()
Watch out

quit_cleanly() is defined once and called from everywhere an exit might happen. This matters more than it looks: in the capstones the same function also closes the data file before quitting, so that pressing Escape half-way through still saves the trials collected so far. Get into the habit now of routing every exit through one function rather than scattering win.close() and core.quit() through your code.

2.3Reading the keyboard with trustworthy timing

The event module from Module 1 is fine for pressing space to move on, but its timing is only as good as your drawing loop. For reaction times you want a tool that timestamps each press against a hardware clock, independent of when your loop happens to look. That tool is the Keyboard object from psychopy.hardware. You create it once, reset its clock at the moment the stimulus appears, then ask it for presses.

from psychopy import visual, core
from psychopy.hardware import keyboard

win = visual.Window(size=[1280, 720], fullscr=False,
                    color='black', units='height')
kb = keyboard.Keyboard()

target = visual.TextStim(win, text='PRESS  F  OR  J', color='white', height=0.06)

target.draw()
kb.clearEvents()          # discard anything pressed before now
win.flip()
kb.clock.reset()          # start timing the instant the target is visible

keys = kb.getKeys(keyList=['f', 'j', 'escape'], waitRelease=False)
while not keys:
    keys = kb.getKeys(keyList=['f', 'j', 'escape'], waitRelease=False)

press = keys[0]
print('You pressed', press.name, 'after', round(press.rt, 3), 'seconds')
win.close()
core.quit()
Watch out

The order of the last three setup lines is the whole game. kb.clearEvents() throws away stray presses from before the trial; the win.flip() puts the target on screen; and kb.clock.reset() starts the clock. Reset the clock before the flip and every reaction time is inflated by up to a whole frame, because the flip waits for the next screen refresh before the target appears. The capstone repeats this exact sequence on every trial, so it is worth getting straight here where there is only one of them.

Try it: when does the clock start? Each trial draws the target, waits for the flip, and then the participant responds. Run a few trials each way and compare the recorded reaction times with the true ones. The screen refreshes every 16.7 ms (60 Hz).

Each key object the Keyboard hands back carries a .name (the key) and a .rt (its reaction time, measured from the last clock reset). A missed trial is simply the case where the loop reaches its deadline and no key was collected, so both stay unset. That is how the capstone records a miss without any special handling.

Note

In the capstone the wait loop is bounded by a deadline, while kb.clock.getTime() < MAX_RT:, rather than looping forever. The idea is identical; it just also gives up after a couple of seconds and records the trial as a miss.

2.4Keeping your stimuli in a file, not the code

Sooner or later you have a list of words, images or item texts too long to sit comfortably in the program. PsychoPy reads a CSV of them for you with data.importConditions, which hands back a list of dictionaries, one per row, with the column headings as keys. Editing, translating or reordering the stimuli then means editing a spreadsheet, not the code.

Suppose a file words.csv holds a single column headed word with one word per row. Reading it is one line:

from psychopy import data

rows = data.importConditions('words.csv')   # list of dicts, one per row
words = [row['word'] for row in rows]        # pull out just the words
print(len(words), 'words loaded; first is', words[0])
Watch out

The key you ask for must match the column heading exactly, spaces and capitals included. row['word'] finds a column headed word, not Word and not " word". A mismatch raises KeyError, which is the single commonest error when reading a conditions file.

The list comprehension [row['word'] for row in rows] is worth reading slowly, because it recurs throughout the capstones. It means: take each row in turn, pull out its word, and collect the results into a new list. Both capstones and both questionnaires read their stimuli this way.

2.5Saving one tidy row per trial: the ExperimentHandler

Module 1 saved nothing, because there was nothing worth saving. From here on every experiment writes a CSV with one row per trial, and the object that does it is the ExperimentHandler. You hand it the participant details once, then on every trial you call addData for each value you want in a column and nextEntry to close the row. When the experiment ends it writes a tidy, R-ready file by itself.

Here is the whole life cycle in one runnable toy: a dialog for the participant code, a handful of pretend trials, and a clean close.

import os
from psychopy import gui, data, core

# 1. Who is sitting down
info = {'participant': '', 'session': '001'}
dlg = gui.DlgFromDict(info, title='Demo')
if not dlg.OK:
    core.quit()
info['date'] = data.getDateStr()

# 2. Where the data go (a data/ folder, a unique filename)
os.makedirs('data', exist_ok=True)
filename = os.path.join('data', f"{info['participant']}_demo_{info['date']}")
thisExp = data.ExperimentHandler(name='demo', extraInfo=info,
                                 dataFileName=filename)

# 3. A few pretend trials
for trial_number in range(1, 6):
    pretend_rt = 0.5 + trial_number * 0.01
    thisExp.addData('trial', trial_number)
    thisExp.addData('rt', pretend_rt)
    thisExp.nextEntry()          # close this row, start the next

# 4. Close cleanly: this is what actually writes the CSV
thisExp.close()
core.quit()

Run it, type a participant code into the dialog, and look in the data folder. You will find a CSV with a row per trial and, on every row, the participant, session and date you typed once. That last point is the quiet convenience of the handler.

Note

Everything in extraInfo is copied onto every row automatically. That is exactly why participant sits beside each trial in R without your ever adding it inside the loop. You set it once, in the dialog, and the handler does the rest.

Watch out

The file is written by thisExp.close(), not trickle-fed as you go. A script that crashes or is force-quit before the close loses the run. This is the deeper reason the capstones route every exit, including the Escape key, through a quit_cleanly() that closes the handler first. Data safety and a clean exit are the same habit.

Try it: where do the rows go? Step through the toy script for participant P01 and watch the rows build up in memory. Then start again and press Escape half-way through.

2.6The shape of every experiment from here

        
Stand back and the five pieces line up into a single skeleton that the rest of the modules simply fill in. A dialog and a handler at the top; stimuli created once; then a loop that, on each pass, draws the stimuli, flips, times a response with the Keyboard, and records the trial; and a clean close at the end. In outline:


# --- setup, once ---
#   dialog for participant details
#   ExperimentHandler with those details
#   create the window, the stimuli, the Keyboard
#   (optionally) read stimuli from a file

# --- the trial loop ---
# for each trial:
#     draw the stimuli
#     kb.clearEvents(); win.flip(); kb.clock.reset()
#     collect a response (with a deadline)
#     work out whether it was correct
#     addData(...) for each column; nextEntry()

# --- close, once ---
#   thisExp.close(); win.close(); core.quit()

        
The serial reaction time task in Module 4 is precisely this skeleton with four circles as the stimuli and a repeating sequence deciding which one lights up. The recognition memory task in Module 5 is the same skeleton with two phases. Once you see the skeleton, the capstones stop being long and start being familiar.
